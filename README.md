# 信义口腔 · 连锁管理系统

连锁口腔门诊管理系统的可运行实现。案例统一为**信义口腔（连锁口腔门诊部）**，数据全部为 mock，不含真实患者信息。

## 两个入口（前端 + 后端按端/模块分离）

系统入口 `http://localhost:3000/` 提供两个入口：数据库结构查看已移入管理端（登录后可见）。

| 入口 | 地址 | 前端文件 | 后端 API 模块 | 面向角色 |
|---|---|---|---|---|
| **客户端（患者手机端）** | `/patient.html` | `patient.html` + `css/patient.css` + `js/patient.js` | `/api/patient/*`、`/api/auth/patient/*` | 患者 |
| **工作人员登录** | `/staff.html` | `staff.html` + `css/auth.css` + `js/staff.js` | `/api/auth/staff/*`、`/api/transfer/*` | 医生/院长/分院负责人/前台/库管/护士 |
| **数据库结构**（管理端内） | `/db.html` | `db.html` + `js/dbview.js` | `/api/db/*`（需登录） | 院长/负责人在管理端菜单进入 |

工作人员登录后**按岗位进入各自工作台**（不是靠入口区分）：

| 岗位 | 登录后的工作台 | 页面 |
|---|---|---|
| 牙医 | 牙医工作站（候诊、病历处方、治疗计划、接诊统计，固定为本人） | `/dentist.html` |
| 院长 | 管理网站（院务、员工与借调、费用、绩效全部模块） | `/admin.html` |
| 分院负责人 | 管理网站（院务、财务、绩效、员工与借调；可看财务、管理其他人） | `/admin.html` |
| 前台 | 管理网站（仅前台运营：签到、队列、结算、随访） | `/admin.html` |
| 库管员 | 管理网站（仅库房：库存台账、采购入库） | `/admin.html` |

## 登录与账号体系

- **患者端**：手机号 + 模拟验证码（演示码 `1234`）登录；登录后只展示本人预约/复诊/套餐，无需重复输手机号。
- **工作人员**：工号 / 姓名 / 手机号 + 密码（演示密码统一 `123456`）登录。注册时需填写「密码」和「确认密码」两次且一致；登录后在管理端或医生工作站右上角点「修改密码」，校验原密码 + 两次新密码一致后可改，旧密码立即失效并向绑定手机号发通知短信。
- **注册与审批**：新员工在 `/staff.html` 点「注册账号」提交，**无需填工号**（系统自动生成），填姓名/手机号/岗位/密码即可，手机号即登录账号。提交后状态为「待审批」，系统向该手机号发送**模拟短信**告知注册已提交（短信留痕于 `sms_message` 表，管理端数据库页可查）；**分院负责人或院长任一方通过即开通**，两方均不通过才最终拒绝，账号状态确定后再次短信告知本人。审批意见写入 `approval_record`，管理端可见。
- **一人多角色**：院长王建国同时拥有「院长 + 牙医」两个角色，登录后可在页面右上角**一键切换身份**（院长工作台 ⇄ 医生工作站）。角色存于 `staff_role` 表，当前身份存于 `staff_session`。

- **医生临时借调**（负责人/院长工作台「医生临时借调」）：发起借调单（选牙医、目标门店、起止日期、事由）→ **负责人或院长任一方通过即生效** → 系统自动**释放原门店该时段的空闲排班**并在**目标门店生成排班**；原门店已有患者预约的时段保留（医生须履约），同一时段不重复排班。两方均不通过才最终驳回。结束借调时清理目标门店未锁定排班。借调期间在目标门店的接诊按 `visit_record.store_id` 计入目标门店绩效。

## 各端功能

- **患者手机端**：验证码登录（**新手机号登录即自动建档成为会员并获赠新客优惠券**）；预约挂号、取消预约（释放号源）、查看复诊提醒并**一键发起复诊预约**、我的套餐卡与治疗计划。
  - **会员与优惠券**：会员享指定项目优惠价（如超声波洁牙会员价 68 元，原价 98）；券可用于洗牙预约或购买套餐抵扣，一次性使用，取消预约自动退回。
  - **洗牙专门挂号**：与牙痛就诊**完全分开**——由洁牙师独立号源（洁牙师＋洁牙椅＋时段）提供，不占用牙医号源；可**用券享会员价 / 用套餐卡扣次 / 到店支付**三种方式，号源满则无法预约。
  - **在线购买洗牙套餐**：患者端模拟支付购买洁牙次数套餐（超声波 258/3 次、喷砂 698/4 次、舒适 1980/6 次），可用券抵扣，支付后自动生成套餐卡。
- **牙医工作站**：固定为登录医生本人；我的候诊队列、书写病历并**开具处方**、开具**治疗计划**（分次期次）、接诊统计。
- **管理网站**（左侧导航按登录岗位过滤）：
  - **费用模块**（院长/分院负责人）：项目收支字典（收费价 vs 材料/人工/分摊成本 vs 毛利）、房租水电等期间费用、医疗产品采购（申请→审批→入库）、利润核算。
  - **绩效模块**（院长/分院负责人）：医生绩效排名（可跨门店筛选）、门店绩效对比。
  - **院务管理**（院长/分院负责人）：经营驾驶舱、排班与椅位、套餐目录、患者档案。
  - **员工与借调**（院长/分院负责人）：医生临时借调、账号审批。
  - **前台运营**（前台）：报到签到、候诊队列、收费结算、随访工作台。
  - **库房管理**（库管）：库存台账（低库存预警）、采购入库。
- **数据库**：40 张表按业务分组展示，可查看字段结构、建表语句（DDL）与模拟数据。

## 数据库与业务规则

- **40 张表**：26 张业务表 + 8 张支撑表（`staff_role`、`patient_session`、`staff_session`、`doctor_transfer`、`store_manager`、`approval_record`、`sms_message`、`refund_request`）+ 6 张会员与洁牙表（`hygienist`、`hygiene_schedule`、`coupon_template`、`coupon`、`hygiene_appointment`、`package_order`），见 `src/schema.sql`。
- **费用口径**：利润 = 项目收入 − 项目成本 − 期间费用；项目成本 = 材料成本 + 人工成本 + 分摊。
- **价目口径（2026 参考价，模拟数据）**：`treatment_item` 共 **64 项**，参考信义口腔公开价目与真实价目表，按类别分层定价。洁牙 98/198/398 元；补牙 260/320/600 元；根管 650/1000/1600 元；种植按品牌分档（登腾 6800 / 奥齿泰 8600 / 雅定 9800 / 诺贝尔 18000），半口 18000、全口 38000；**正畸按儿童/成人 × 矫治器类型分 21 档**（儿童普通托槽 7000、国产自锁 8800、进口自锁 11800；成人普通托槽 8000、国产自锁 9800、进口自锁 12800；隐形按思迈康 12800 / 美加 15800 / 时代天使 19800 / 隐适美 29800 分档；保持器 400/800）。同一"矫正"因人群与方案不同收费不同，符合真实定价逻辑。实际价格随地区与政策波动，此处仅用于作业演示。
- **治疗计划明细**：患者手机端「我的 → 我的治疗计划」点击计划可查看各期次明细；医生工作站治疗计划明细可查看期次与金额。治疗合同与知情同意书均为线下签署，不纳入系统。
- **绩效口径**：按（门店、月份、牙医）统计接诊人次、项目收入、售卡数，绩效金额 = 收入 × 提成比例。
- 其他规则：同患者同日仅一条有效预约；号源锁定/释放；过敏史提示；套餐快照与扣次；跨门店归集；跨诊所排班不可冲突；发票一期人工登记。

## 本地运行（无需 Docker）

```bash
npm install
DB_MODE=memory npm run dev
# 打开 http://localhost:3000 进入系统入口
```

`DB_MODE=memory` 使用内存 PG 模拟库并自动灌入 mock 数据，适合演示与答辩。关闭服务数据即重置。

## 华为云 Flexus + Portainer 部署

### 方式一：Portainer 里粘贴 Compose（推荐）

1. Portainer → **Stacks** → **Add stack**。
2. Name 填 `xinyi-dental`。
3. Build method 选 **Web editor**，把 `docker-compose.yml` 全文粘贴进去。
4. 在 **Environment variables** 里填：
   - `POSTGRES_DB` = `xinyi_dental`
   - `POSTGRES_USER` = `xinyi`
   - `POSTGRES_PASSWORD` = 自定义强密码
   - `APP_PORT` = `3000`
5. 需要把项目文件放到服务器上时：先把整个 `dental-chain` 目录上传到服务器（如 `/opt/xinyi-dental`），在 Web editor 里把 `build.context: .` 改为 `/opt/xinyi-dental`，或直接在 Portainer 里选择 **Repository / Upload** 方式挂载目录。
6. 点 **Deploy the stack**。首次构建约 1–3 分钟。
7. 访问 `http://服务器公网IP:3000`（安全组需放行 3000 端口），从入口页进入。

> 应用启动时会建表并自动写入 mock 数据；数据持久化在 `pgdata` 卷中，重启不丢。

### 方式二：服务器上命令行

```bash
cd /opt/xinyi-dental
cp .env.example .env
# 修改 .env 里的密码
docker compose up -d --build
docker compose ps
```

### 常用运维

```bash
docker compose logs -f app      # 应用日志
docker compose logs -f worker   # 复诊提醒 worker
docker compose down             # 停止（数据保留）
docker compose down -v          # 停止并清空数据库卷
```
