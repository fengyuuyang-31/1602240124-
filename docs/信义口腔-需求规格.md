# 信义口腔连锁管理系统 · 功能规格（spec.md）

> Spec-kit 第 1 阶段产出物。输入：课堂板书（问题 / 背景 / 知识库 → 需求）与用户口述需求；受 `constitution.md` 约束。

**版本**：1.0
**日期**：2026-11-24
**状态**：已实现

---

## 1. 问题与背景

连锁口腔门诊在扩张过程中出现四类问题：

1. **预约混乱**：患者无法自行查号、取消后号源不释放；医生可约时段不清，跨门店排班可能撞车。
2. **身份混杂**：医生、院长、前台、库管、患者混在同一个入口；院长本人也出诊，一个账号需要两种身份。
3. **成本不清**：项目收费与材料/人工/分摊成本没有对应关系，房租水电、采购、利润无法核算。
4. **绩效难算**：医生被临时借调到分店后，业绩算在原店还是目标店没有依据。

系统目标：规范预约与排班、降低预约取消造成的号源浪费、提高医生积极性、可平滑扩展到更多门店。

## 2. 角色与用户故事

| 角色 | 核心故事 | 验收要点 |
|---|---|---|
| 患者 | 我想在手机上按门店查号并预约，临时有事可以取消 | 登录后只看到本人数据；取消后号源立即释放；可一键发起复诊预约 |
| 牙医 | 我想查看候诊队列并书写病历、开处方和治疗计划 | 只能操作分配给本人的就诊；处方不可重复开具 |
| 前台 | 我想做签到、队列、结算和随访 | 不能看利润与绩效；收费后账单可发起退款申请 |
| 库管员 | 我想看库存并做采购入库 | 只看采购与库存，看不到成本利润；采购需审批 |
| 分院负责人 | 我想看本门店财务、绩效并审批注册/借调/退款 | 与院长任一通过即可生效；审批留痕 |
| 院长 | 我需要全量经营视图，同时保留出诊身份 | 右上角一键切换院长 ⇄ 牙医；审批权不得被旁路 |

## 3. 功能需求

### FR-1 入口与登录

- **FR-1.1** 系统入口 `/` 提供三个独立入口：患者手机端、工作人员登录、数据库查看。
- **FR-1.2** 患者用手机号 + 模拟验证码 `1234` 登录；令牌为 `x-patient-token`。
- **FR-1.3** 工作人员用工号 / 姓名 / 手机号 + 密码登录；令牌为 `x-session-token`。
- **FR-1.4** 注册无需工号，系统自动生成；手机号即登录账号；需填两次密码且一致。
- **FR-1.5** 注册提交后向手机号发送模拟短信并在 `sms_message` 留痕；账号状态为“待审批”。
- **FR-1.6** 工作人员可修改密码：校验原密码、两次新密码一致、新旧不同，旧密码立即失效并发短信。
- **FR-1.7** 一人多角色切换；停用账号不得登录或继续访问。

**验收**：用 `XY001 / 123456` 登录可切换为医生；新注册账号在审批前登录被拒；审批通过后短信与账号状态同步更新。

### FR-2 患者端

- **FR-2.1** 按门店、日期查询可约号源，只显示医生可约时段。
- **FR-2.2** 预约时校验：医生在该时段有排班、椅位不冲突、该患者当日无有效预约、号源未锁定。
- **FR-2.3** 取消预约释放号源，且只能取消本人预约。
- **FR-2.4** 复诊提醒列表可一键转为复诊预约。
- **FR-2.5** 查看本人套餐卡剩余次数与治疗计划。
- **FR-2.6** 所有查询按令牌反查的手机号过滤，请求参数中的手机号一律忽略。

**验收**：患者 A 伪造参数查询患者 B 的预约返回空；取消后号源 `locked` 减 1。

### FR-3 牙医工作站

- **FR-3.1** 候诊队列固定为登录医生本人，不接受前端传入的医生 ID。
- **FR-3.2** 写病历前校验就诊记录归属本人；开具处方带幂等保护。
- **FR-3.3** 可创建分期治疗计划并查看历史计划与处方。
- **FR-3.4** 接诊统计分别给出接诊人次与去重患者数。

### FR-4 管理端（按岗位过滤）

- **FR-4.1** 排班与椅位管理、套餐目录、患者档案、经营驾驶舱（院长 / 负责人）。
- **FR-4.2** 签到、候诊队列、收费结算、随访（前台，院长 / 负责人亦可用）。
- **FR-4.3** 库存台账、低库存预警、采购入库（库管，院长 / 负责人亦可用）。
- **FR-4.4** 注册审批、退款管理、医生临时借调（院长 / 负责人）。
- **FR-4.5** 菜单按角色过滤，且后端逐接口校验，前端隐藏不是安全边界。

### FR-5 医生临时借调

- **FR-5.1** 借调单包含医生、目标门店、起止日期、事由，由负责人或院长审批。
- **FR-5.2** 审批通过后：释放原门店该时段的**空闲**排班，保留已有预约的班；在目标门店逐椅位生成排班并写 `transfer_id`。
- **FR-5.3** 同一时段不重复排班；审批与生成排班在同一事务内完成。
- **FR-5.4** 结束借调只删除本单生成且未锁定的排班。
- **FR-5.5** 借调期间在目标门店的接诊按 `visit_record.store_id` 计入目标门店绩效。

### FR-6 费用与绩效

- **FR-6.1** 项目字典含 64 项 2026 参考价，逐项维护收费价与材料/人工/分摊成本。
- **FR-6.2** 期间费用录入（房租、水电等），支持按期间查询。
- **FR-6.3** 采购流程：申请 → 审批 → 入库，审批人取自令牌。
- **FR-6.4** 利润 = 收入 − 项目成本 − 期间费用；成本按最新 `effective_date` 版本取值。
- **FR-6.5** 医生绩效按（门店、月份、医生）归集接诊人次、去重患者数、项目收入、售卡数，写入 `doctor_performance`。
- **FR-6.6** 绩效支持跨门店筛选与门店对比，体现借调后的实际出诊门店。

### FR-7 退款与幂等

- **FR-7.1** 可对已收费账单发起退款申请，填写金额与原因。
- **FR-7.2** 金额必须大于 0；累计退款不得超过原账单 `payable`。
- **FR-7.3** `idempotency_key` 唯一，重复提交返回原申请，不生成第二笔。
- **FR-7.4** 负责人或院长任一方通过即退款，审批时二次校验额度，通过后冲减账单。

### FR-8 价目分层与明细查看

- **FR-8.1** 价目按人群与方案分层：正畸分儿童/成人 × 矫治器类型共 21 档，种植按品牌分档，同一项目不同方案收费不同。
- **FR-8.2** 治疗计划支持动态添加多个期次，每期选项目、日期与预计金额，同一计划可含不同收费的项目。
- **FR-8.3** 患者在手机端「我的 → 我的治疗计划」点击计划可查看各期次明细（期次、项目、日期、金额、状态）。
- **FR-8.4** 处方列表可点击，弹出患者信息、诊断与处方明细。
- **FR-8.5** 治疗合同与知情同意书均为线下签署，不纳入系统。

### FR-9 数据库查看

- **FR-9.1** 展示 40 张表，按业务分组，可看字段结构、DDL 与模拟数据。
- **FR-8.2** 明确标注全部为模拟数据。

## 4. 非功能需求

| 编号 | 要求 |
|---|---|
| NFR-1 | 前端静态资源禁用缓存，避免演示时旧脚本残留 |
| NFR-2 | 本地日期按运行机器时区计算，不得因 UTC 偏移跨日 |
| NFR-3 | API 请求 6 秒超时，前端失败必须给出可见提示，不得卡在“加载中” |
| NFR-4 | 本地演示 `DB_MODE=memory` 一键启动；正式环境 PostgreSQL + Docker |
| NFR-5 | app 与 worker 并发初始化数据库须加事务级 advisory lock |
| NFR-6 | 界面淡蓝色系，术语统一 |

## 5. 范围边界（本期明确不做）

- 不接真实微信支付，支付为模拟；退款为业务审批 + 账单冲减。
- 不接真实短信网关，短信在 `sms_message` 表留痕。
- 不绑定真实微信小程序 AppID / CloudBase；患者端为可在浏览器演示的手机端页面。
- 发票不做自动核验，一期人工登记。
- 不使用真实患者数据。

## 6. 成功标准

1. 两个入口均可从 `/` 进入并完成各自完整流程。
2. 40 张表可在数据库管理端查看，seed 数据完整。
3. 预约取消、借调、退款、审批、绩效跨店归集五条核心链路通过实测。
4. 未授权角色访问受限接口返回拒绝，不返回业务数据。
5. `npm run build` 通过；`docker compose up -d --build` 可启动。
